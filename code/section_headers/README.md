# Выделение разделов патента

Подготовительный эксперимент к структурной нарезке патентов для векторного поиска и RAG.

## Суть

**Цель.** Проверить, можно ли автоматически, без ручной разметки, выделить разделы в описании патента (уровень техники, сущность, подробное описание и т.д.). Если нельзя, нарезка по разделам неприменима.

**Данные.** 37 727 патентов США (покрытия), поле `Description`.

**Метод.**
1. Словарь заголовков: последовательности слов капсом, стоящие в начале предложения и за которыми начинается текст раздела; в словарь попадают те, что встречаются хотя бы в `MIN_DOCS` патентах.
2. Каждый заголовок словаря относится к одному из 8 типов разделов по ключевым словам (`BACKGROUND` → уровень техники, `SUMMARY` → сущность, …). Таблица `data/header_groups.csv` правится вручную, строки с `source=manual` не перезаписываются.
3. В каждом патенте ищутся заголовки; раздел тянется от своего заголовка до следующего.
4. Для сравнения описание режется так же, как бейзлайн `run_sentences_10_1`: по 10 предложений с перекрытием 1, и считается, сколько фрагментов пересекают границу раздела.
5. Дополнительно (`--clusters`): заголовки кластеризуются по эмбеддингам названия, текста под ним и позиции в описании, кластеры сравниваются с группами по ключевым словам (ARI, силуэт).

**Метрики.** Доля патентов, где найден хотя бы один раздел; доля патентов с каждым типом раздела; длина разделов в символах, словах и предложениях; доля фрагментов бейзлайна, пересекающих границу раздела.

## Результаты

| | |
|---|---|
| Вариантов заголовков в словаре | 291 → 8 типов разделов |
| Патентов, где найдены разделы | **98,5%** (37 149 из 37 727) |
| Типов разделов на патент | обычно 5–6 (64% патентов), в среднем 5,15 |
| Фрагментов бейзлайна, пересекающих границу раздела | 10,1% (из 1,54 млн); хотя бы один такой фрагмент есть в 99,3% патентов |

| Раздел | Есть у патентов | Доля описания | Предложений, медиана (10–90%) |
|---|---|---|---|
| Подробное описание | 89% | 63% | 180 (61–445) |
| Примеры | 46% | 25% | 78 (22–236) |
| Сущность | 86% | 13% | 18 (5–62) |
| Уровень техники | 91% | 8% | 16 (6–46) |
| Чертежи | 75% | 6% | 14 (5–57) |
| Ссылки | 56% | 4% | 7 (4–20) |
| Область техники | 58% | 1% | 2 (2–4) |

Короткие разделы (уровень техники, сущность, чертежи) по длине сопоставимы с одним-двумя фрагментами по 10 предложений, поэтому нарезка по длине смешивает их с соседними. Подробное описание занимает около 20 фрагментов, и для структурной нарезки его нужно делить дальше.

Ограничения: проверено, что разделы найдены, но не то, что их границы верны; заголовки, не попавшие в группы (`other`, 16% патентов), режут текст, но в число типов не входят.

## Запуск

```bash
pip install -r requirements.txt
python -m unittest discover -s tests       # тесты
python main.py --limit 300 --output /tmp/smoke   # пробный прогон
python main.py                             # весь эксперимент, ~2 мин
python plots.py                            # рисунки по results/
python main.py --clusters                  # с кластеризацией заголовков (нужны umap-learn, sentence-transformers)
```

Корпус (`collected_patents.jsonl`, по патенту в строке, поля `ID` и `Description`) кладётся в `data/` или передаётся через `--input`; все параметры — в `config.py`. При `--limit` таблица `data/header_groups.csv` не перезаписывается.

Входные и выходные данные (`data/`, `results/`, `figures/`) в репозиторий не добавляются, см. `.gitignore`: `data/header_groups.csv` строится заново при первом запуске, остальное — `main.py` и `plots.py`.

## Структура

- `config.py` — параметры: пути, `MIN_DOCS`, размер фрагмента и перекрытие, параметры кластеризации.
- `main.py` — единственная точка запуска эксперимента.
- `plots.py` — рисунки; читает только `results/`, эксперимент не перезапускает.
- `src/data.py` — чтение корпуса; `src/headers.py` — словарь и поиск заголовков; `src/sections.py` — разделы, длины, фрагменты; `src/stats.py` — сбор и сохранение результатов; `src/clusters.py` — кластеризация заголовков.
- `tests/` — юнит-тесты.

## Выход

`results/`:
- `summary.json` — сводные числа из таблицы выше;
- `sections.csv` — по типам разделов: доля патентов, доля описания, длины (среднее, медиана, 10%, 90%) в символах, словах, предложениях;
- `headers.csv` — заголовки: тип, источник (словарь или ключевые слова), в скольких патентах, пример;
- `orders.csv` — последовательности разделов в патентах;
- `no_headers.csv` — патенты без разделов;
- `per_patent_headers.jsonl` — найденные заголовки и их позиции по патентам;
- `clusters/` — результаты `--clusters`.

`figures/`:
- `sections_presence.pdf` — доля патентов с каждым разделом;
- `sections_lengths.pdf` — длина разделов в предложениях: медиана и разброс от 10% до 90% патентов;
- `header_clusters.pdf`, `k_scan.pdf` — после `--clusters`.
